# Claim Matrix

WhatIf Freight Router is an auditable, tri-source, selective minimum-cost certification engine for freight-route recommendation under incomplete search, biased evidence, and ambiguous preferences.

This top-level file is the reviewer-facing claim index. It records current theorem-backed, empirical, heuristic-but-measured, and non-claim / descriptive-only implementation evidence. The expanded rationale, caveats, and evidence notes live in [`docs/claim_matrix.md`](docs/claim_matrix.md). The matching negative-evidence companion lives in [`negative_results.md`](negative_results.md). Formal proof maturity is tracked separately in `docs/theorem_map.md`. It does not mark still-open `G11.*` or `P14.*` requirements as green.

## Claim Status Language

- `theorem-backed`: supported by an explicit theorem/proposition package that is named consistently in code, tests, artifacts, and docs.
- `empirical`: supported by checked code, tests, artifacts, or evaluator outputs.
- `heuristic-but-measured`: an engineering or heuristic component with checked measurement, artifact, or evaluator support, but no theorem-backed guarantee.
- `non-claim / descriptive only`: repository framing, navigation, negative scope, or implementation description rather than a performance or validity claim.

If a row depends on named support, calibration, or model assumptions, that conditionality is called out in the Notes field rather than by introducing a separate fifth primary status.

When no theorem or proposition id is currently published for a row, this file marks that explicitly as `none-published-in-this-slice` rather than inventing an id. Artifact-path cells use one of four explicit forms: exact checked local artifact files, exact reviewer-package index entries, artifact-family globs for runtime surface families, or an explicit `not-applicable` marker.
